# App Description

## Проект

- Название: `fitness-app`
- Стек: `React Native`, `Expo`, `TypeScript`
- Назначение: приложение для записи тренировок, упражнений и результатов

## Что уже сделано

- Инициализирован новый проект через `create-expo-app` с шаблоном `blank-typescript`
- Установлены базовые зависимости:
  - `@react-navigation/native`
  - `@react-navigation/native-stack`
  - `react-native-screens`
  - `react-native-safe-area-context`
  - `@react-native-async-storage/async-storage`
  - `axios`
- Создана стартовая структура папок внутри `src/`
- Подключен корневой `NavigationContainer` и `Native Stack`
- Подготовлены заготовки для:
  - API-клиента
  - конфига API
  - локального хранилища
  - theme-констант
- Созданы `README.md` и `.env.example`
- Реализован стартовый flow первого запуска приложения
- Добавлены 2 стартовых экрана:
  - экран ввода имени при первом запуске
  - экран приветствия с именем пользователя и `uuid`
- Добавлено локальное хранение данных экземпляра приложения в `AsyncStorage`
  - сохраняются `name` и `uuid`
  - при удалении данных экран возвращается к первому запуску
- При старте приложения проверяется наличие сохраненного экземпляра:
  - если `uuid` найден, сразу открывается второй экран
  - если `uuid` отсутствует, показывается экран ввода имени
- На первом экране реализован UI в темном брутальном стиле на основе референса из `temp/code.html`
- Настроено корректное поведение при открытии клавиатуры:
  - форма поднимается вверх
  - кнопка остается видимой
- Обновлен `SafeAreaView` на версию из `react-native-safe-area-context`
- Настроен светлый `StatusBar` для темного интерфейса

## Текущее состояние

- Проект уже содержит рабочий onboarding первого запуска
- Есть базовая логика локальной идентификации пользователя без бэкенда
- Навигация переключает стартовые экраны в зависимости от данных в `AsyncStorage`
- Подготовлена база для следующих экранов приложения и дальнейшей бизнес-логики

## Договоренности на данный момент

- Локальные данные будут храниться в `AsyncStorage`
- Данные экземпляра приложения хранятся по отдельному ключу `fitness-app/instance`
- Часть данных приложение будет синхронизировать с бэкендом через HTTP API
- Для маршрутизации используется `React Navigation`
- Переменные окружения для Expo будем хранить через `EXPO_PUBLIC_*`
- На текущем этапе `uuid` генерируется локально на устройстве при первом вводе имени

4. После этого подключить реальные сценарии создания и просмотра тренировок.
